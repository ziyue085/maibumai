# 买不买 AI（maibumai）

私人消费决策 Skill。对着 WorkBuddy 说一句「这个值不值得买」，它会读你的画像、查价格、算真实成本，给出**四选一明确结论**：建议购买 / 建议替换方案 / 建议暂缓 / 不建议购买。

不是比价工具，不是导购，也不是记账软件。

---

## 它解决什么问题

问 AI「这个值不值得买」，通常得到三种没用的回答：

1. **把判断推回来**：「要看你的实际需求，因人而异。」
2. **只劝省钱**：「建议理性消费，非必需品可以再想想。」
3. **顺着买**：「这款好评很多，性价比不错，可以入手。」

第一种是逃避，第二种是说教，第三种是导购。**maibumai 要给出一个能被复核、被推翻、被记账跟踪的结论。**

---

## 四件事让它和普通建议不一样

### 1. 结论由规则算出来，不由模型宣布

模型负责取证、追问、给理由；结论由脚本按固定优先级解析：

```
硬拦截 > 换方案 > 暂缓 > 购买
```

只要理由里有「已有可用同类」，无论列多少优点，结论都是「不建议购买」。
**「理由都指向暂缓，结论却写建议购买」这种自相矛盾，在结构上不可能发生。**

### 2. 财务判断是强制的，不是建议

`月可支配 = 月收入 − 固定支出 − 储蓄目标 − 每月投资额`

- 超过自设单笔硬上限 → **引擎直接判「不建议购买」**，模型没有裁量权
- 超过月可支配但未越硬上限 → 强制「建议暂缓」
- 重决策但没填预算 → 直接拦住，要求先补画像，不许瞎猜

这条是 v0.2 最重要的改动。v0.1 里财务模块只是"算了个数放在那里"，模型可以视而不见——被独立审核抓到，已修。

### 3. 数字必须可核验，且分三道门

| 门 | 管什么 |
|---|---|
| `financial` | 预算、硬上限、你自设的约束（不买二手、不订阅） |
| `integrity` | 价格有没有来源、是否过期、是不是外币没换算、金额是否为正 |
| `coherence` | 结论与理由是否自洽、暂缓有没有复查条件、等级有没有被调低 |

三道门各报各的，不混为一谈。外币没汇率、价格过期、订阅没写周期，都过不去。

### 4. 享受型消费不被劝退

系统里有专门的「情绪价值成立」判定，四条门槛（来源具体 / 不是跟风 / 预算内 / 不重复）满足就明确支持，不加「但是」。

测试用例 V01 守着这条线：680 元的演唱会门票判成「暂缓」即视为失败。

## 个人画像：越用越准

画像按**事实**存在 `~/.maibumai/profile.json`，每条带更新日期。

- **财务**：月收入、固定支出、储蓄目标、月投资额、应急金、单笔硬上限
- **投资**：可投资本金、每月投入、长期年化预期（没填就不做复利演示，绝不替你假设收益率）
- **生活与偏好**：阶段、居住环境、价格敏感度、是否接受二手
- **约束**：不买二手 / 不订阅 / 必须可携带——违反即不建议购买

**可支配余额是算出来的，不是问出来的。** 收入 2600、固定支出 1100、储蓄 300、投资 400 → 可支配 800。一笔 6800 的相机等于 8.5 个月的全部可支配余额，这个数字比任何劝说都有力。

维护规则：已填且未过期的**不再问**；过期的**先确认再用**（收入半年、偏好一年）；缺失的只补当前判断真正需要的。

> **不因为你有储蓄就默认没压力，也不因为你是学生就一律劝省。** 身份标签不进任何计算，进计算的只有数字和你自己设的约束。

## 安装

```bash
git clone <repo> ~/.workbuddy/skills/maibumai
# 或直接把目录复制过去
```

无依赖：纯 Python 标准库，无第三方包、无 API Key、不调用任何模型接口。

首次使用（可选，建议做）：

```bash
python scripts/mbm.py init
python scripts/mbm.py profile set finance.monthly_income=2600 \
    finance.monthly_fixed_expense=1100 invest.monthly_contribution=400
```

之后直接在对话里说「我想买这个，值不值」就行——**不需要自己填规则码，也不需要跑命令行**。

数据默认在 `~/.maibumai`，**刻意放在仓库之外**；可用 `MAIBUMAI_HOME` 改位置。

---

## 命令行（给模型用，不是给用户用）

```bash
M=~/.workbuddy/skills/maibumai/scripts/mbm.py
python $M brief                                   # 画像 + 已有物品，一眼看全
python $M profile gaps --limit 3                  # 该补/该确认什么
python $M judge --input draft.json --human        # 判定 + 落账（一步）
python $M check --input draft.json --human        # 只看判定
python $M outcome <id> --bought yes --decision BUY
python $M review  <id> --input review.json
python $M due / stats / export / doctor
```

草稿格式见 `schemas/decision.schema.json`，示例见 `examples/`。

## 边界

**它不做什么**

- 不推荐商品、不做比价、不代替下单
- 不评价你的消费观
- 不在信息不足时硬给结论，也不为了给结论而编信息

**它做不到什么**

- 无法核实截图里的价格是否已失效（只能标为用户提供并提示风险）
- 无法知道你的真实身体状况、家庭财务细节
- 使用频率预测本质是猜测，只能靠复盘逐步校准
- 需要登录或反爬的页面取不到价，只能是「未核实」

**已知风险**

- 规则码是人为设计的，漏掉了人情压力、面子、家庭共同决策等维度
- 阈值（500 元门槛、6 倍月预算、14/7/3 天保鲜期）是经验取值，不是统计结论
- 复盘依赖你主动回报，不回报就没有校准
- 引擎保证一致性，**不保证正确性**——理由选错了，结论会内部自洽但实际错误
