# 买不买 AI（maibumai）

一个私人使用的消费决策 Skill。用户带来一笔具体消费——商品名、价格、链接或截图——它会给出**四选一明确结论**：建议购买 / 建议替换方案 / 建议暂缓 / 不建议购买。

不是比价工具，不是导购，也不是记账软件。

---

## 它解决什么问题

问 AI "这个值不值得买"，通常得到三种没用的回答：

1. **把判断推回来**："要看你的实际需求，因人而异。"
2. **只劝省钱**："建议理性消费，非必需品可以再想想。"
3. **顺着买**："这款好评很多，性价比不错，可以入手。"

这三种都不叫判断。第一种是逃避，第二种是说教，第三种是导购。

maibumai 要做的是一件更难的事：**给出一个可以被复核、被推翻、被记账跟踪的结论。**

---

## 它怎么做到

### 1. 结论是规则算出来的，不是"想"出来的

模型负责取证、追问、给理由码；结论由脚本按固定优先级解析：

```
硬拦截 > 换方案 > 暂缓 > 购买
```

只要理由里有 `DUP_OWNED`（已有可用同类），无论列了多少优点，结论都是"不建议购买"。**"理由都指向暂缓，结论却写建议购买"这种自相矛盾，在结构上不可能发生。**

### 2. 每个数字都要有来源和日期

价格主张必须带 `source_type` + `url` + `observed_at`。超过保鲜期（数码 7 天 / 其他 14 天 / 促销价 3 天）的价格不能当现价用。

只有用户口述的价格，**不足以支撑"价格合理"的判断**——审计会拦下来。

### 3. 享受型消费不被劝退

这是设计上最容易被做错的地方。系统里有专门的 `EMOTIONAL_VALUE_LEGIT` 码，四条门槛全满足就明确支持购买，不附加"但是"。

测试用例 V01 就守着这条线：680 元的演唱会门票，判成"暂缓"即视为失败。

### 4. 会记账，也会复盘

每次判断写入本地账本，记录当时对使用频率的预测。60 天后复盘实际使用情况，统计出"你平均高估几倍"。

下次判断时用这个倍数修正：

> 你说每周用 3 次。你过去 6 次复盘里，实际使用平均是预测的 1/3。
> 按每周 1 次算，这个 2400 的东西单次成本是 40 元，不是 13 元。

这句话的说服力，来自它是用户自己的数据。

## 安装

```bash
git clone <repo> ~/.workbuddy/skills/maibumai
# 或直接把目录复制到 ~/.workbuddy/skills/maibumai
```

无需安装依赖：纯 Python 标准库，无第三方包，无 API Key，不调用任何模型接口。

初始化数据目录：

```bash
python scripts/mbm.py init
python scripts/mbm.py profile set budget.discretionary_monthly=3000
```

数据默认存在 `~/.maibumai`，**刻意放在仓库之外**。可用环境变量 `MAIBUMAI_HOME` 改到别处。

---

## 使用

在 WorkBuddy 里直接说"这个值不值得买"就会触发。命令行也能单独跑：

```bash
python scripts/mbm.py profile show                # 看画像
python scripts/mbm.py owned find --query 耳机      # 查已有物品
python scripts/mbm.py check --input draft.json    # 校验一份判断草稿
python scripts/mbm.py log   --input draft.json    # 写入账本
python scripts/mbm.py due                         # 待复盘清单
python scripts/mbm.py stats                       # 闲置率 / 高估倍数
```

草稿格式见 `schemas/decision.schema.json`，示例见 `examples/`。

## 边界

**它不做什么**

- 不推荐商品、不做比价、不代替下单
- 不评价用户的消费观
- 不在信息不足时硬给结论，也不为了给结论而编信息

**它做不到什么**

- 无法核实截图里的价格是否已失效（只能标记为用户提供 + 提示风险）
- 无法知道用户真实的身体状况、家庭财务细节
- 使用频率预测本质上是猜测，只能靠复盘逐步校准
- 对平台反爬、需要登录才能看的页面，取不到价就只能是"未核实"

**已知风险**

- 规则码体系是人为设计的，可能漏掉真实决策里的重要维度（比如"面子""人情"）
- 阈值（500 元门槛、6 倍月预算、7 天保鲜期）是经验取值，不是统计结论，需按个人情况调整
- 复盘依赖用户主动回报，不回报就没有校准
