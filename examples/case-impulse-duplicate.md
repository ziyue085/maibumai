# 案例二：冲动消费

> 这类案例考验的是：**能不能看出"需求"是被折扣制造出来的。**

## 用户输入

> 空气炸锅五折！299，本来 599，限时到今天。买不买？

## 判断过程

**分级**：299 元，品类"家电/厨电" → L2。

**已有物品查询**：`owned find --query 炸锅` →

```
- 飞利浦空气炸锅 4L｜家电/厨电｜good｜2023-11 购入
```

状态 `good`。这是决定性信息。

**需求诊断**：一问（合并了两个缺口）——

> 你之前那台大概多久用一次？

用户答："呃……好像半年没开了。"

**判定理由码**：

| 码 | 依据 |
|---|---|
| `DUP_OWNED` | 已有 4L 空气炸锅，状态良好，功能覆盖 |
| `IMPULSE_SIGNAL` | 用户自述"本来没打算买"，动机是五折 + 限时 |
| `USAGE_IMPLAUSIBLE` | 上一台半年使用 < 3 次 |

→ **不建议购买**（硬拦截 `DUP_OWNED` 短路，后面两个码只是补充说明）

**取证说明**：这个案例里价格其实不需要核实——无论 299 还是 199，结论都不变。**为一个已经被否决的购买去查价，是浪费。** 但 `product.price` 仍记录用户所说金额，标记 `user_provided`。

## 输出

```
【结论】不建议购买

【一句话】你家里那台 4L 的半年没开过，这台买回来大概率是同一个结局。

【为什么】
· 已有可用同类：2023 年买的 4L 那台，状态良好 —— DUP_OWNED
· 动机来自折扣：你自己说"本来没打算买" —— IMPULSE_SIGNAL
· 使用频率存疑：上一台半年用不到 3 次，5L 不会让它变得更好用 —— USAGE_IMPLAUSIBLE

【如果确实想改善做饭】
把那台搬出来用两周。用得顺，不需要新的；用不顺，说明问题不在设备大小。

【记录】
已记账。60 天后如果你还是买了，我会来问你用了几次——不是催你，是想知道这次判断准不准。
```

## 这个案例在防什么

**防"折扣即理由"**。常见的错误输出：

> 五折确实划算，如果家里没有空气炸锅可以入手。

问题在于"如果"——它把判断推回给了用户，而用户恰恰是来问这个"如果"成不成立的。

另一个错误是去核实"599 是不是虚高标价"。这个案例里不必要：**已被硬拦截的购买，不需要再花时间比价。**

## 判定要点

三个码里，只有 `DUP_OWNED` 是硬拦截。另外两个是解释"为什么会想买"——这部分对用户有价值，因为它解释了冲动从哪来。

**注意**：如果旧的那台是 `broken`，`DUP_OWNED` 不成立，结论会翻转成"建议购买"。同一件商品，旧物状态不同，结论相反——这就是为什么 `owned.json` 的 `condition` 字段必须认真填。
