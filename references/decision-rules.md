# 决策规则手册

结论不是"想出来的"，是**规则码解析出来的**。你负责取证和给码，优先级由脚本执行。

## 一、总则

- 优先级固定：**硬拦截 > 换方案 > 暂缓 > 购买**。命中即短路，后面的正向理由不能翻盘。
- 唯一的例外：**只被钱挡住时**（`BUDGET_BREACH` / `BUDGET_TIGHT` / `UNAFFORDABLE_DEBT`），
  如果替代方案合格且在承受范围内，结论是「建议替换方案」而不是「不建议购买」。
  重复持有、诈骗、违反硬约束**不让位**。
- 一条理由一个码，`note` 写具体依据（谁、多少、什么时候）。**只有码没有依据的，等于没给理由**，引擎会拦。
- 同一条理由不要拆成两个码凑数。
- 码与结论不一致时，以脚本解析结果为准，不要自己改结论。
- 有些码**不用你给**：`BUDGET_BREACH`、`BUDGET_TIGHT`、`BUDGET_UNVERIFIED`、`AFFORDABLE_WITHIN_BUDGET`、`CONSTRAINT_VIOLATION` 由引擎按画像与价格自动判定并强制注入。你给了也会被丢弃——预算结论不是模型能宣布的事。

## 二、硬拦截 → 不建议购买

### `DUP_OWNED` 已有可用的同类物品

**成立（三条全满足）**

1. 已有物品能满足**同一个使用场景**（不是"同一品类"）。
2. 该物品状态是 `good` 或 `worn`。`failing` / `broken` 不算重复——那是替换需求，反而支持购买。
3. 用户说不出旧物具体哪里不能用。

**订阅尤其要查**：两个功能重叠的会员，每月各扣一笔，退订比退货难得多。
引擎会把子品类相同的在用资源列出来（`numbers.resources.similar`），
如果结论里完全没回应"是否重复"，审计会给一条 `AUD_RESOURCE_IGNORED` 警告。

**常见误用**：把"我有耳机"当成"不需要第二副耳机"。通勤降噪和运动防水是两个场景。判重复看**场景**，不看品类。

### `BUDGET_BREACH` 超过承受上限

**只有两种情况成立**（都由引擎判定，不需要你给）：

1. 价格 > 用户**自设**的单笔硬上限——这是他自己划的线，一票否决。
2. 价格 > 可自由消费资金 + 一年结余——**真正的安全风险**：砸锅卖铁也拿不出。

**不成立的情况**（这里最容易错）：

- 价格超过"6 个月收入"——**这不是红线**。有储蓄、收入不稳定的人，问题不是月收入撑不住，而是这笔钱该不该从存量里出。
- 没设预算、没填存量——这是"不知道"，用 `INFO_GAP` 去问，不要替他假设。

**常见误用**：把"很贵"当"买不起"。贵是感受，买不起是算式。

### `UNAFFORDABLE_DEBT` 需要借贷或动用应急金

**成立**：需要分期还款、借钱、动用应急金、挪用房租学费等刚性支出。

**常见误用**：把"免息分期"一律当借贷。只有当月还款会挤占必要开支时才算。

### `SCAM_SIGNAL` 诈骗或假货信号

**成立（任一）**：价格低于官方价 50% 且无合理解释；要求私下转账或脱离平台交易；无正规渠道与售后；评价高度同质化；预售方无资质。

**常见误用**：把"便宜"当"假货"。官方清仓、二手、老款退市都是正常低价。

### `PATTERN_REPEAT` 同品类反复闲置

**成立**：账本中同品类已有 ≥2 次复盘为闲置（`uses_per_month < 1` 或 `would_buy_again = false`）。

**证据来源**：`mbm.py stats` 的 `idle_by_category`。**不许凭印象说"你以前也这样"**——必须有记录。

### `CONSTRAINT_VIOLATION` 违反用户自己设的硬约束

**成立**：商品与画像中的结构化约束冲突——

- `no_used`：用户说过不买二手，商品是二手/翻新
- `no_subscription`：用户说过不再增加订阅，商品是订阅
- `must_be_portable`：用户要求可携带，商品标明不可携带

**这个码由引擎自动判定并强制注入**，不需要你手工加。你唯一要做的是如实转述：
"你之前说过不买二手，这台是二手的，所以结论是不建议。"

**常见误用**：把"我一般不太喜欢"当成硬约束。硬约束是用户明确声明过的开关，不是你的印象。

## 三、换方案 → 建议替换方案

**这一层有资格关。** 命中换方案理由不等于能输出"建议替换方案"——
替代品必须同时满足下面五条，缺一条就自动降为「建议暂缓」：

| 项 | 要求 |
|---|---|
| 名称 | 具体型号或可检索的名称 |
| 价格 | 正数，且已换算到基准币种（外币要有 3 天内的汇率证据） |
| 来源 | 能核实它真的存在、真的卖这个价 |
| 周期 | 订阅类必须写计费周期，否则年化成本无从比较 |
| 预算 | 换过去之后仍然在你的承受范围内（不能换成更买不起的） |
| 出处 | 有一条 `subject: alternative` 的价格证据，不能只在理由里写"更便宜" |

**为什么这么严**：「换一个更便宜的」是这套系统最常给出的建议，也是唯一无法被用户验证的建议。
推荐一个买不起、或者有价无据的东西，比不推荐更糟。

### `SUBSTITUTE_ADEQUATE` 有更便宜的路径

**成立**：存在另一条路径能满足主要需求（约 80% 以上），且用户能接受。

**必须给出**：替代品名称、价格、来源、它能满足多少、牺牲了什么。

**常见误用**：提出"理论上更便宜"但用户明确排斥的方案（"别买了，多喝热水"）。那是说教，不是替代方案。

### `SPEC_MISMATCH` 规格与用途不匹配

**成立**：参数与自述用途冲突——内存不够剪 4K、功率带不动、尺寸放不下、接口不兼容。

**必须指出**：哪个参数不够、需要什么水平、对应产品是什么。

### `PRICE_ABOVE_FAIR` 现价高于同类合理区间

**成立**：同规格可比渠道的中位价明显低于当前报价（>10%），或官方价明显高于该产品的常规区间。

**证据要求**：至少两个独立来源，且规格可比（同容量、同保修、同版本）。

**常见误用**：拿不同配置、不同保修、翻新机比全新机。

## 四、暂缓 → 建议暂缓

暂缓必须带**复查条件**，否则就是没答。写清"什么时候、看到什么就买"。

### `IMPULSE_SIGNAL` 动机来自外部刺激

**成立（任一）**：购买动机主要是"打折 / 限时 / 限量 / 别人都有"；说不出具体使用场景；首次接触不到 24 小时且此前无需求。

**不成立**："我找这个型号找了两个月""旧的那个上个月坏了"——这是 `NEED_REAL`。

### `TIMING_ADVERSE` 时机不对

**成立**：有证据表明换代或大促在 4 周内（官方预告、产品页显示"新品即将发布"、历年固定大促节点）。

**还必须满足"等待划算"**——三个条件缺一不可：

1. 预期差价 ≥ 商品价格的 5%；
2. 等待时间 ≤ 2 周，或者用户并不急用；
3. 差额的绝对值值得为它多跑一趟（比如 200 元的东西省 10 元，不值得）。

**常见误用**（这是本规则最危险的失效方式）：**看到任何促销节点就暂缓**。
"明天有活动"永远成立，那样什么都不能买。差价太小、或者用户今天就要用，就该直接给"建议购买"，顶多在回答里提一句"明天可能有活动"。

`UX` 上更糟的一种：用户问 200 块的东西值不值，答"等明天"。他要的是判断，不是购物日历。

### `PRICE_STALE` / `PRICE_UNVERIFIED`

判据见 `evidence-policy.md`。处理方式：结论降级为暂缓，并给出重新取价的具体方式。

### `INFO_GAP` 关键信息缺失

**成立**：缺的字段会改变结论（价格未知、型号不明、用途不清、预算不明）。

**不成立**：缺的字段不影响结论（不知道颜色、不知道包装）。不要为了显得严谨而追问无关项。

### `USAGE_IMPLAUSIBLE` 场景与真实使用模式冲突

**成立**：自述用途与品类普遍使用模式冲突，且用户给不出具体的每周安排。

典型：买跑步机减肥、买面包机做早餐、买单反学摄影、买投影替代电视。

**处理**：给"30 天验证条款"——先借用、租用、按次付费，验证使用频率后再买。这比直接否决更有效。

### `BUDGET_TIGHT` 需跨月支出

**成立**：价格 > 月结余，但 ≤ 可动用存量 + 12 个月结余。

**处理**：说明这笔钱挤掉了什么（"等于把旅行基金推后 1.4 个月"）。
**这不是"买不起"**——它只是需要时间或需要从存量里出。

### `BUDGET_UNVERIFIED` 承受力无法确认

**成立**（三种之一）：

1. 收入、固定支出、可动用存量都不足以判断；
2. 月结余是在"储蓄目标/每月投资未填"的情况下估出来的**上界**，而这笔消费吃掉了其中一半以上；
3. 金额本身还没定下来（外币换不出来等）。

**处理**：结论是**暂缓**，不是否决。第一位的事是补数据，不是放弃。
**不要说"你买不起"**——你还不知道他买不买得起。

## 五、正向 → 支撑建议购买

| 码 | 成立条件 |
|---|---|
| `NEED_REAL` | 需求先于接触商品存在，且能说出具体场景与频率 |
| `SUBSTITUTE_INADEQUATE` | 现有替代方案确实不够用（旧物失效、功能缺口） |
| `PRICE_FAIR` | 现价处于同类合理区间，有 ≥2 个可比来源 |
| `AFFORDABLE_WITHIN_BUDGET` | 价格 ≤ 月可支配，不挤占刚性支出 |
| `EMOTIONAL_VALUE_LEGIT` | 见下方四条 |
| `DURABILITY_GAIN` | 替换失效旧物，预期服务周期 ≥ 2 年 |
| `LOW_REGRET_RISK` | 可退换 / 二手残值高 / 后悔成本低 |

### `EMOTIONAL_VALUE_LEGIT` 的四条门槛

这是最容易被滥用的码，也是**最不该被压制**的码。四条全满足才算：

1. 用户能说出具体的情感来源（"听了五年""结婚纪念""一直想去现场"）。
2. 不是"好看 / 便宜 / 别人都有 / 拍照好看"。
3. 在预算内。
4. 不与已有物品重复。

四条满足 → 给正向，**明确支持，不加"但是"**。
第 1 条不满足 → 那其实是 `IMPULSE_SIGNAL`。

## 六、优先级冲突的处理

| 情况 | 结果 | 理由 |
|---|---|---|
| 硬拦截 + 一堆优点 | 不建议购买 | 优点不能让"已有同类"失效 |
| 硬拦截 + 人工驳回 | 仍不建议购买 | 驳回只允许在无硬拦截时使用 |
| 换方案理由 + 没给替代品 | 暂缓 | 没具体替代品的"换方案"是空话 |
| 只有价格理由（便宜、划算） | 暂缓 | 折扣不是购买理由，缺需求锚点 |
| 正向 + 一条暂缓理由 | 暂缓 | 暂缓理由指向"现在不能判断"，不是"永远不买" |

## 七、不适用本框架的场景

机械套用会得出荒谬结论。遇到这些，先说明判断标准不同：

- **医疗、安全、法律必需品**：不存在"值不值"，先满足需求，再谈性价比。
- **送礼**：价值由收礼人决定，不是自用逻辑；但预算约束仍然有效。
- **工作刚需且可报销**：成本归属不同，不占用个人可支配预算。
- **替代生命必需品的支出**（如净水器、安全座椅）：按风险规避逻辑，不按享受型逻辑。
