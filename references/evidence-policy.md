# 证据政策

这一层存在的唯一目的：让"编造价格""拿两个月前的价格当现价""把一条评论当普遍口碑"从**可能发生**变成**可被检测并阻断**。

---

## 一、来源分级

| 级别 | 类型 | 例子 | 能用来断言什么 |
|---|---|---|---|
| S1 | `official` | 品牌官网、官方旗舰店、官方公告、官方参数页 | 官方定价、规格、在售状态 |
| S2 | `authorized_retail` | 平台自营、授权经销商 | 实际成交价、库存 |
| S3 | `third_party` | 第三方店铺、比价站、聚合站 | 可作为价格参考，须注明非官方 |
| S4 | `user_provided` | 用户截图、口述、聊天记录 | **只能作为线索**，不能支撑"价格合理" |
| S5 | `ugc` | 内容社区、开箱视频、评论区 | 只能作为口碑线索，不能作为价格依据 |

**规则**：
- 断言"价格合理"必须至少有 S1–S3 中的一条。
- 只有 S4 的价格 → 可以用于暂缓判断，但不能给出"建议购买"（审计会拦）。
- S5 的价格一律回源核实，不直接采信。

---

## 二、时效

| 主张类型 | 保鲜期 | 说明 |
|---|---|---|
| 公开报价（`price`，快变品类） | **7 天** | 数码、电子、服饰、鞋、美妆、游戏 |
| 公开报价（`price`，其他） | **14 天** | 家具、家电、乐器等 |
| 促销价 / 券后价（`promo`） | **3 天** | 活动随时结束，过夜就可能失效 |
| 历史价格曲线（`price_history`） | 7 天 | 用于"是否历史低位"的判断 |
| 规格参数（`spec`） | 365 天 | 产品未换代时有效 |
| 口碑 / 评测（`review`） | 180 天 | 须标注是否为换代前的评测 |
| 召回 / 质量事件（`safety`） | 30 天 | 必须是最新状态 |

超过保鲜期的处理，**只有两个选项**：
1. 重新取价，用新证据；
2. 结论降级为暂缓，并写明"价格需要重新确认"。

**没有第三个选项**：不能"参考一下""大概差不多"。

---

## 三、价格口径必须说清

同一个商品可以有五个"价格"，混用就是误导：

- 标价 / 到手价 / 券后价 / 会员价 / 分期价
- 是否含运费、是否含税
- 是否含赠品、是否以旧换新
- 是否为国行、是否含保修

写证据时用 `claim` 字段把口径写全，例如：
`{"kind":"price","claim":"自营到手价 1899（含税不含运费，2026-10-28）","value":1899,...}`

`product.price` 与证据 `value` 相差超过 5% 会被审计判为 `AUD_PRICE_MISMATCH`——这时要交代口径差异，不是改数字。

**金额必须是正的有限数。** 没有数值（"大概一千多"）、负数（"返现后 -500"）、
布尔、`NaN`、`Infinity` 的价格证据都会被直接拦下：`EV_PRICE_VALUE_INVALID`。

### 币种：不同币种的数字不许直接比

用户预算以 `profile.meta.base_currency`（默认 CNY）计价。商品或证据是外币时必须给汇率：

```json
{"kind":"fx","claim":"USD/CNY 7.10","value":7.10,"base":"USD","quote":"CNY",
 "source_type":"official","url":"https://...","observed_at":"2026-10-28"}
```

没有**可用**的汇率 → `EV_CURRENCY_UNCONVERTED` 阻断，商品价变成"未知"，结论不可能给出"建议购买"。

理由很简单：899 美元和 899 人民币，差 7 倍。**宁可判不了，也不能拿错币种的数字比较。**

汇率是唯一直接乘进价格的数字，所以它比价格更严，**九关全过才进算式**：

| 关 | 不过会怎样 | 驳回码 |
|---|---|---|
| 币种在可换算列表内（CNY/USD/EUR/JPY/HKD/GBP/KRW/TWD/SGD） | 不换算 | `FX_BAD_CURRENCY` |
| 币种对完整、两侧不同 | 不换算 | `FX_NO_PAIR` / `FX_SAME_PAIR` |
| 数值是正的**有限**数（`nan`/`inf`/布尔/超大整数都不行） | 不换算 | `FX_BAD_VALUE` |
| 数量级在 1e-4 ~ 1e4（绝对边界，拦的是"根本不像汇率"的量级） | 不换算 | `FX_OUT_OF_RANGE` |
| **这个币种对有锚点可参照**（v0.9） | 不换算 | `FX_NO_ANCHOR` |
| **偏离该币种对的锚点不超过 5 倍** | 不换算 | `FX_IMPLAUSIBLE` |
| 来源等级 ≤ 3（官方/授权/专业站） | 不换算 | `FX_WEAK_SOURCE` |
| 有可点开的链接 | 不换算 | `FX_NO_LINK` |
| 日期在 3 天内且不晚于基准日 | 不换算 | `FX_NO_DATE` / `FX_FUTURE_DATE` / `FX_STALE` |

币种进了支持列表却没补锚点，以前会**默认放行**（没参照就等于没闸门）。
现在一律 `FX_NO_ANCHOR`，并由 `check_repo.py` 做一致性断言：
`fx_anchor_gaps()` 必须为空。**新增币种请同步补 `FX_ANCHORS`。**

倒数第二关是 v0.8 加的，因为**绝对区间管不住"区间内但不合理"**：
`USD/CNY=1` 与 `=100` 都落在 1e-4~1e4 里，却离真实量级差了 7 倍和 14 倍。
前者把 100 美元算成 100 元（直接判成买得起），后者算成 10000 元（把买得起的判成买不起）。
锚点是各币种对人民币的**数量级参照**（2026-10 前后）：

```
CNY 1.0   USD 7.1   EUR 8.2   JPY 0.047   HKD 0.91
GBP 9.5   KRW 0.0052   TWD 0.22   SGD 5.5
```

⚠️ 锚点不是实时汇率，**新增币种必须重新校准**——尤其 VND / IDR 这类小面额币种，
沿用 5 倍会把真实汇率误杀。锚点距基准日超过 365 天时自动放宽到 50 倍并发
`EV_FX_ANCHOR_OLD` 警告：拿三年前的锚点卡 5 倍，等于把过期数据当事实。

**五层分开看，别合成一句"汇率没问题"**：`fx_rate_report()` 分别报

| 层 | 通过代表什么 |
|---|---|
| `validity` 合法性 | 是正的有限数，能进算式 |
| `coverage` 锚点覆盖 | 有内置锚点可参照，能谈"合不合理" |
| `plausibility` 合理性 | 没有离谱到量级都不对 |
| `source` 来源可信度 | 出处看得过去（币种认得、等级够、有链接、日期新） |
| `content` 页面内容核验 | **永远是 False**：汇率证据也只有链接格式，没有正文可核 |

九关全过只说明"没有理由拒绝它"，发的是 INFO 级 `EV_FX_PLAUSIBLE_ONLY`。

### 换算方向、冲突与交叉汇率（v0.9 明确）

字段语义固定为 **`value` = 1 `base` 值多少 `quote`**：

```json
{"kind":"fx","value":7.1,"base":"USD","quote":"CNY", ...}   // 1 USD = 7.1 CNY
```

- **换算只走 `fx_rates()` 一个入口**。`convert_amount()` / `to_base()` 都只认它
  返回的表，不存在"先算出来、事后拦截"的路径。
- **同一币种对多条汇率**：7.1 与 7.9 相差 >1% → **整对丢弃**，不许"取最新一条"。
  两个方向互不自洽（`r₁ × r₂` 偏离 1 超过 5%）→ 双向丢弃。
- **不相关币种对**：GBP/KRW 在基准是 CNY、又连不到 CNY 时不进换算表
  （`FX_UNRELATED_PAIR`）。`fx_rejection()` 的 `base` 参数就是用来判这件事的。
- **交叉汇率**：允许借**一个**中间币种（EUR→USD→CNY），链上的每一段都要过完整闸门，
  结果标注 `EV_FX_CROSS_USED` 并写明推导链。更深的一律不算——每段都带误差，
  串得越长越不可信。
**差 3%~30% 的汇率照样能通过**——本仓库没有独立的实时汇率源，所以不许说"汇率已核实"。

**过期的汇率不是"只警告照用"，而是根本不进计算**——换算失败会阻断，
报 `EV_FX_UNTRUSTED`（说明为什么不能用）+ `EV_CURRENCY_UNCONVERTED`（价格因此未知）。
先算出来、再拦下来是没有意义的：一个被乘坏的价格已经进了等级、预算和结论。

### `subject`：区分"这个商品"和"用来比价的商品"

比价是判断的核心动作，但**品牌款 2680 与国产同类 1280 不是"价格冲突"，那正是"贵不贵"的结论本身**。

所以价格证据要标 `subject`：

- `target`（默认）——被评估商品本身的价格。同一商品多个来源不一致，才是冲突。
- `reference`——用来比价的参照商品（市场行情）。不参与冲突检测，也不参与 `product.price` 的口径核对。
- `alternative`——**推荐的替代品**自己的报价。这是「建议替换方案」唯一的合法性来源。

```json
{"kind":"price","claim":"旗舰店 2680","value":2680,"source_type":"official",...}
{"kind":"price","claim":"同规格国产 1280","value":1280,"subject":"reference",...}
{"kind":"price","claim":"记忆棉腰靠 180","value":180,"subject":"alternative",...}
```

漏标 `reference` 会导致大量误报，最终让人忽略警告——比没有警告更糟。
漏标 `alternative` 则直接让"建议替换方案"不成立：**没有出处的"更便宜"，用户无法核实。**

### 冲突：谁和谁比，才算冲突

**先确定是不是同一个商品，再讨论价格。** 评估顺序固定为：

```
1 品牌与型号  2 规格/SKU  3 地区与版本  4 税费与交易条件  5 价格口径  6 来源可信等级  7 可比较的价格
```

比较键是 `(model, variant, region, price_basis)`——身份三元组在前，口径在后。
**口径优先级只能在身份匹配之后使用**：促销价 899 属于 128GB、标价 1099 属于 256GB 时，
按"促销优先"挑 899，等于替用户选了最便宜的规格，那不是价格判断。

| 字段 | 取值 | 说明 |
|---|---|---|
| `price_basis` | `tax_inclusive` / `street` / `promo` / `msrp` / `tax_exclusive` | 不填视为 `unknown` |
| `variant` | 如 `128GB`、`256GB` | 规格不同的报价**不是同一商品** |
| `region` | 如 `CN`、`US` | 地区差价是正常的商业事实 |

- **口径不同 → 不是冲突**（`EV_PRICE_BASIS_DIFF`，警告）：
  官网建议零售价 1099 与授权商城促销价 899 可以同时为真；
  128GB 与 256GB、国行与美版、含税与不含税同理。
  把它们塞进同一把尺比大小，得到的"冲突"是假的。
- **到手价只认一个口径**：优先级 `tax_inclusive > street > promo > msrp > tax_exclusive`。
  标价与促销并存时取促销；含税与不含税并存时取**含税**——用户说 899（不含税）时
  实际要付 1099，这正是"口径不同"掩盖掉的真问题。
- **同等级、同口径的价互相差 5% 以上才是事故**（`EV_PRICE_CONFLICT`）：
  至少有一个是错的，取平均、取最新、取便宜的都是在替用户挑，结论降为暂缓。
  **没标口径又差 5% 以上**时同时发 `EV_PRICE_BASIS_UNKNOWN`：既可能是真打架，
  也可能只是口径不同，补齐口径前不下购买结论。
- **规格或地区并列、又没标你要买哪个 → 缺信息暂缓**（`IDENTITY_AMBIGUOUS`，
  对外报 `EV_IDENTITY_AMBIGUOUS`）。理由是"分不出该拿哪个价去比"，
  **不是**"至少有一个是错的"，也**不许默认选最便宜的规格**。
  用户明确指定规格时只收吻合的报价：没标规格的报价不等于"就是那个规格"。
- **跨等级差异只报警告**（`EV_CONFLICT`）：官方 1299 与第三方 999 不同很正常，
  要说明差异、采信等级更高的那个，**不得取平均**。
  ⚠️ **身份并列时不发这条**——它写的是"同一商品在多个来源价差 N%"，
  与"这不是同一件商品"自相矛盾；此时价差并进 `EV_IDENTITY_AMBIGUOUS` 里说。
- **`subject=reference` 的价不参与冲突**：品牌款 2680 与国产同类 1280 不是冲突，
  那正是"这个品牌贵不贵"的结论本身。
- **低可信报价不能用来"凑近"输入价**：官方 1200、社区 899、用户说 900，
  不能因为 899 与 900 吻合就认定"价格对得上"——那只是和一个不可信的数字对上了。
  核对只认可信来源（等级 ≤ 3），且只比**最高等级那一档**。

### `page_price` 只是自述；`page_text` 才是可复核的页面内容

`page_price` 是取证方读完页面后**原样**记下的价格。四种填法，别混为一谈：

| 填法 | 判定 | 结果 |
|---|---|---|
| 正数且与 `value` 一致（±2%） | 成立 | `price_verified = reported`（**取证方自述**） |
| 正数但与 `value` 差 2% 以上 | 自相矛盾 | `EV_QUOTE_CONTENT_MISMATCH`，不给替换建议 |
| 0 / 负数 / 布尔 / `NaN` / `Infinity` | 不成立 | `EV_PAGE_PRICE_INVALID`，**换不来任何等级** |
| 不填或填 `null` | 没读过 | `price_verified = source`（只到"出处看得过去"） |

**只填 `page_price` 拿不到"页面核对过"**——引擎手里没有任何页面内容，无从复核。
要拿到 `content` 级，另外给可复核的内容（任选，给得越多越强）：

| 字段 | 作用 |
|---|---|
| `page_text` | 页面上包含该价格的一段正文（或全文）。**`content` 级必须有它** |
| `page_text_sha256` | 这段正文的 sha256，引擎会**重算**比对，不符判 `EV_PAGE_TEXT_HASH_MISMATCH`；要求哈希核验却没给 → `EV_PAGE_TEXT_HASH_REQUIRED`；声明了哈希却没给正文 → `EV_PAGE_TEXT_HASH_UNVERIFIABLE` |
| `page_price_set` | **只此一项拿不到 `content`**：那是取证方列的一串数字，不是可复核的页面正文，最多算自述 |

**页面里的数字还必须有价格语义。** `产品型号 X699，支持256GB存储，当前售价899元` 里
699 与 256 都是数字，但都不是价签。引擎按货币单位（元/¥/USD…）与价格表达
（售价 / 到手价 / 优惠后 / 券后 / 促销价…）判语境，
落在型号、容量、销量、评分、日期这类位置的数字一律不算价格：

| 页面内容 | 报价 699 |
|---|---|
| `型号 X699，售价899元` | 不算价 → `EV_PAGE_TEXT_NOT_A_PRICE` |
| `已售699件，售价899元` | 不算价 → `EV_PAGE_TEXT_NOT_A_PRICE` |
| `售价699元` / `优惠后699元` | 算价，通过 |
| 同一数字既有价格用法又有非价格用法 | 判**不确定** → `EV_PAGE_TEXT_PRICE_AMBIGUOUS`，不强行通过 |

引擎在正文里找不到这个价 → `EV_PAGE_TEXT_NO_QUOTE`，结论降为暂缓。
**报价上下文验证是三者里唯一能真正证伪的检查**，哈希只证明正文没被改过。

结果里两件事分开写，别混：

- `text_integrity` —— 正文完整性（`verified` / `not_provided` / `mismatch`）；
- `source_authenticity` —— 网页来源真实性，**恒为 `unverified`**。

⚠️ 三件做不到的事，别当成已核实：

1. 哈希只证明"你给的正文与你声明的哈希一致（中途没被改）"，
   **不**证明这段正文来自那个 URL——取证方贴一段自己写的、哈希自洽的文字，
   照样能拿到 `content` 级（`tests/run_regression.py::Q7` 已把这条固化为断言）；
2. **不能**证明域名是官方渠道；
3. **不能**证明现在还是这个价（抓取留痕只在 `fetched_at` 那一刻有效）。

替代品的报价要和 `alternative.price` 相差 5% 以内，并且会先换算到基准币种再比对——
100 美元记成「便宜 800」是最常见也最危险的一种错。

而且只对得上数值不算有据。一条替代品报价要同时满足：

1. **来源等级 ≤ 3**（官方 / 授权渠道 / 第三方专业站）。用户口述、截图、内容社区只能当线索；
2. **有可点开的链接**，不是一句"某平台"；
3. **有观测日期**，且在保鲜期内（电子类 7 天，其余 14 天）；
4. **换算到基准币种**后仍与 `alternative.price` 一致。

缺任何一条，结论都会降为「建议暂缓」并说明差哪一项——不会给出一条用户无法核实的"更便宜"。

## 四、来源冲突

两个来源价差超过 15% 时：

1. **不得取平均**。平均出来的数字在任何一个渠道都买不到。
2. 按等级采信最高等级来源；同级则采信更新的一条。
3. 在输出里说明差异与原因（不同配置 / 不同渠道 / 一个含运费 / 一个是秒杀价）。
4. 无法解释的低价，先怀疑是假货或引流价。

## 五、查不到怎么办

这是最容易出问题的地方。**查不到不是失败，编一个才是。**

| 情况 | 处理 |
|---|---|
| 页面打不开、被反爬 | 记为"未核实"，请用户粘贴价格文本或截图 |
| 只有旧价 | `PRICE_STALE`，暂缓，给重查方式 |
| 型号太新、全网无报价 | `PRICE_UNVERIFIED`，暂缓，等上市或有货 |
| 型号太旧、已停产 | 说明已停产，价格参考二手行情，标注为二手 |
| 只有商品名、无型号 | 先问型号。型号不明时任何比价都无意义 |

禁止的替代说法：
- ❌ "这类产品一般在 2000 元左右"（没查就是编）
- ❌ "据我所知最近降价了"
- ❌ "大概在这个区间"
- ✅ "没查到 30 天内的公开报价，所以现在没法判断贵不贵。"

## 六、五种不得输出的表述

出现即视为编造，审计会拦：

1. **"历史最低价""全网最低""史低"**——除非有 `price_history` 类证据。
2. **"质量很好""口碑不错"**——必须指向具体来源；一条评论不是口碑。
3. **"能用三五年"**——使用寿命是估计值，必须标注为估计并给出依据（保修期 / 实测 / 用户反馈）。
4. **"这个价很值"**——必须有可比价格，否则只能说"无法判断"。
5. **"大家都说……"**——没有出处的共识等于没有。

---

## 七、截图与链接的特殊处理

**截图**：
- 价格标为 `user_provided`，不能当市场价。
- 检查截图里的时间戳、活动标签、是否含"券后"字样。
- 截图常见陷阱：秒杀倒计时已过期、满减未满足、区域价、会员专享价。

**链接**：
- 打开后确认三件事：商品是否在售、价格是否与你引用的一致、规格是否与你判断的一致。
- 同一链接不同 SKU 价格差很多，必须确认是哪一个 SKU。
- 链接失效或跳转到首页 → 视为未核实。

---

## 八、什么时候可以"不查"

只有 L1（≤100 元）快判可以跳过取证。其余情况，**"我觉得不用查"不是理由**。

例外：用户明确说"不用查，我就是想让你帮我分析一下"。此时结论里必须写明"基于你提供的信息，未做独立核实"，并且不能给"价格合理"这类判断。
